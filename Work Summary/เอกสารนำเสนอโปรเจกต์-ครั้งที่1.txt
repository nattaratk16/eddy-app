 1. ข้อมูลทั่วไปของโปรเจกต์
========================================================================

  ชื่อโปรเจกต์ : EDDY (มีมาสคอตชื่อ "เอ็ดดี้")

  ประเภท      : เว็บแอปพลิเคชัน (Web Application) จัดตารางชีวิต/ปฏิทิน
                ผสาน AI และระบบทำงานกลุ่ม

  แนวคิดหลัก  : แอปปฏิทินคล้าย Google Calendar + ผู้ช่วย AI (Gemini)
                + ระบบกลุ่มที่ให้ AI ช่วยหาเวลาว่างร่วมและกระจายงาน

  ปัญหาที่แก้  : - คนทั่วไปจัดตารางชีวิต/งาน/สิ่งที่ต้องทำได้ยาก กระจัดกระจาย
                - การนัดงานกลุ่ม/หาเวลาว่างที่ตรงกันของหลายคนเสียเวลา
                - เครื่องมือปฏิทินทั่วไปไม่ได้ช่วย "คิด/วางแผน" ให้

  กลุ่มเป้าหมาย : นักเรียน/นักศึกษา จนถึงคนทำงาน (ออกแบบให้ครอบคลุมทุกวัย)

  จุดขายหลัก   : AI ช่วยวิเคราะห์ตาราง + ระบบกลุ่มที่ AI หาเวลาว่างตรงกัน
                แล้วกระจายงานให้อัตโนมัติ

 2. เทคโนโลยีที่ใช้ (Technology Stack)
========================================================================

  Frontend / Framework
    - Next.js 14.2.5 (App Router)  — ทั้ง frontend และ backend ในตัวเดียว
    - React 18.3.1
    - TypeScript                    — type safety ทั้งโปรเจกต์
    - Tailwind CSS                  — ระบบดีไซน์ (ธีม "Genie" ฟ้า-เมฆ)
    - ฟอนต์ IBM Plex Sans Thai

  Backend / Database
    - Next.js API Routes            — REST API
    - Prisma 5.17 (ORM)
    - PostgreSQL บน Neon (cloud database)

  Authentication
    - NextAuth v5 (Auth.js)
    - Email/Password (เข้ารหัสด้วย bcrypt)
    - Google OAuth (ล็อกอินด้วยบัญชี Google)

  AI
    - Google Gemini API
    - โมเดล : gemini-flash-lite-latest

  ไลบรารีเสริม
    - framer-motion 11   : อนิเมชัน/ลูกเล่น
    - @dnd-kit           : ลากสลับลำดับ subtask
    - date-fns           : จัดการวันที่/ปฏิทิน
    - lucide-react       : ไอคอน
    - bcryptjs           : เข้ารหัสรหัสผ่าน
    - clsx               : รวม class ของ Tailwind


========================================================================
 3. สถาปัตยกรรมระบบ (System Architecture)
========================================================================

  รูปแบบ : Full-stack แบบ monolith ด้วย Next.js (frontend + backend
           อยู่ในโปรเจกต์เดียว)

  ชั้นการทำงาน (Layers)

    [ผู้ใช้ / เบราว์เซอร์]
          |
    [Frontend - React/Next.js pages]   หน้าเว็บ + UI
          |
    [API Routes - Next.js]             ตรรกะ backend + ตรวจสิทธิ์
          |
    +--------------------+-------------------+
    |                    |                   |
 [Prisma ORM]      [NextAuth]          [Gemini API]
    |                    |                   |
 [PostgreSQL/Neon]  [Google OAuth]     [Google AI]

  หลักการออกแบบ AI (จุดเด่น)
    - งาน "ภาษา / ตัดสินใจเชิงบริบท"  ->  ใช้ Gemini
    - งาน "เวลา / ตัวเลขที่ต้องแม่นยำ" ->  ใช้อัลกอริทึมคำนวณเอง (local)
    - ทุกฟีเจอร์ AI มี fallback เป็นตรรกะ local เมื่อ AI ล่ม
      (แอปไม่พังแม้ AI ใช้ไม่ได้)

 4. โครงสร้างฐานข้อมูล (Data Model — 13 ตาราง)
========================================================================

  --- กลุ่มผู้ใช้ & การล็อกอิน ---

  User               ผู้ใช้ (อีเมล, ชื่อ, รูป, รหัสผ่าน hashed,
                     username, bio/นิสัย, avatar สี+อีโมจิ,
                     เวลาที่สะดวก dayStart/dayEnd, timezone)
  Account            บัญชี OAuth (มาตรฐาน NextAuth)
  Session            เซสชันล็อกอิน
  VerificationToken  โทเคนยืนยัน

  --- ปฏิทิน & งาน ---

  Category           หมวดหมู่ปฏิทิน (ชื่อ + สีพาสเทล 16 สี)
  Event              กิจกรรมในปฏิทิน (วัน, เวลาเริ่ม-จบ, สถานที่, หมวดหมู่)
  Task               สิ่งที่ต้องทำ (ความสำคัญ, กำหนดส่ง, เวลาที่ใช้ประเมิน)
  Subtask            รายการย่อยในงาน (มีลำดับสำหรับลากสลับ)

  --- AI ---

  ChatMessage        ประวัติแชทกับเอ็ดดี้

  --- ระบบกลุ่ม (เฟส 3) ---

  Group              กลุ่ม (ชื่อ, รายละเอียด, สี, เจ้าของ)
  GroupMember        สมาชิกกลุ่ม (บทบาท, สถานะคำเชิญ pending/accepted,
                     ตั้งค่าความเป็นส่วนตัว showEventTitles)
  GroupTask          งานของกลุ่ม (ชื่อ, เวลาที่ใช้, กำหนดส่ง)
  GroupTaskAssignment ผลการมอบหมายงาน (ใครทำ, วัน-เวลา, สถานะ,
                     event ที่สร้างในปฏิทินส่วนตัวตอนยืนยัน)


========================================================================
 5. ฟีเจอร์ทั้งหมดของระบบ
========================================================================

  5.1 ระบบสมาชิก (Authentication)
      - สมัครสมาชิก / เข้าสู่ระบบด้วยอีเมล-รหัสผ่าน
      - เข้าสู่ระบบด้วย Google (OAuth)
      - ป้องกันหน้าที่ต้องล็อกอิน (middleware + layout guard)
      - หน้า Landing / Get Started + splash intro ก่อนเข้าล็อกอิน

  5.2 ปฏิทิน (Calendar) — สไตล์ Google/Apple
      - มุมมอง วัน / สัปดาห์ / เดือน สลับได้
      - Time-grid มีแกนเวลา, กิจกรรมชนกันวางเคียงกันอัตโนมัติ,
        เส้นบอกเวลาปัจจุบัน
      - คลิกช่องเวลาว่าง = เพิ่มกิจกรรม, คลิกกิจกรรม = แก้ไข
      - หมวดหมู่ปฏิทิน 16 สีพาสเทล + ตัวกรองแสดง/ซ่อน
      - มินิปฏิทิน + สรุปสัปดาห์ด้วย AI

  5.3 สิ่งที่ต้องทำ (To-do List)
      - เพิ่ม/แก้/ลบงาน + ระดับความสำคัญ + กำหนดส่ง
      - Subtask (รายการย่อย) พร้อมลากสลับลำดับได้
      - AI แตกงานใหญ่เป็น subtask อัตโนมัติ
      - Priority Score : คำนวณคะแนน "ควรทำก่อน" (importance/urgency/effort)
      - เรียงงานตามที่ AI แนะนำ + ป้าย "ควรทำก่อน"

  5.4 ผู้ช่วย AI (Eddy) — เฟส 2
      - แชทกับเอ็ดดี้ (รู้บริบทตาราง + นิสัยผู้ใช้)
      - พิมพ์ข้อความ -> แปลงเป็นกิจกรรม/งานอัตโนมัติ
      - วิเคราะห์ความหนาแน่นตาราง + เตือนเวลาชนตอนสร้างกิจกรรม
      - สรุปภาพรวมสัปดาห์
      - ทุกฟีเจอร์มี fallback เป็นตรรกะ local

  5.5 ระบบกลุ่ม (Group System) — เฟส 3 *** ฟีเจอร์เด่น ***

      3a) กลุ่ม + สมาชิก + คำเชิญ
          - สร้างกลุ่ม, เชิญเพื่อนด้วยอีเมล
          - ระบบคำเชิญ (ต้องกดรับก่อน pending -> accepted)
          - จัดการสมาชิก / ออกจากกลุ่ม / ลบกลุ่ม

      3b) ปฏิทินกลุ่ม
          - เห็นตารางของสมาชิกทุกคนซ้อนกัน (แยกสีต่อคน)
          - ความเป็นส่วนตัวรายคน : แต่ละคนเลือกได้ว่าจะให้เพื่อนเห็น
            "ชื่อกิจกรรม" หรือแค่ "ไม่ว่าง"

      3c) งานกลุ่ม + AI หาเวลาว่าง + กระจายงาน  *** หัวใจของโปรเจกต์ ***
          - เพิ่มงานที่ต้องช่วยกันทำ (ชื่อ, เวลาที่ใช้, กำหนดส่ง)
          - AI หาเวลาว่างของสมาชิกทุกคน (จากปฏิทิน + เวลาที่สะดวก)
          - AI กระจายงานให้แต่ละคนลงในช่วงว่าง อย่างเป็นธรรม

      3d) ยืนยันงาน (Approve)
          - สมาชิกกดยืนยันงานที่ได้รับ -> สร้างเป็นกิจกรรมในปฏิทินส่วนตัว
          - เห็นได้ทั้งปฏิทินตัวเองและปฏิทินกลุ่ม

  5.6 โปรไฟล์ผู้ใช้ (Profile)
      - ชื่อ, username, อวาตาร์ (อีโมจิ+สี หรือรูปจากบัญชี Google)
      - "นิสัย/ตัวตน" (bio) : เอาไปให้ AI วิเคราะห์ปรับคำแนะนำให้เข้ากับคน
      - ช่วงเวลาที่สะดวก + timezone : ป้อนให้ AI หาเวลาว่าง
      - การ์ดสถิติ (จำนวนกลุ่ม/หมวดหมู่/กิจกรรม/งานที่ทำสำเร็จ)

  5.7 ดีไซน์ / UX
      - ธีม "Genie" ฟ้า-เมฆ สดใส ทันสมัย
      - ฟอนต์ IBM Plex Sans Thai
      - อนิเมชันด้วย framer-motion (ลูกเล่นลื่นไหล)
      - รองรับมือถือ (responsive) + แถบเมนูล่างบนมือถือ


========================================================================
 6. AI ในระบบ (รายละเอียด — จุดที่ควรเน้นตอนนำเสนอ)
========================================================================

  โมเดลที่ใช้ : Gemini "gemini-flash-lite-latest"
                (เลือกเพราะเร็ว ~1 วินาที + ประหยัด เหมาะกับงานในแอป)

  ** จุดเด่นเชิงวิชาการ : สถาปัตยกรรมแบบ Hybrid **

    ปัญหา "จัดตาราง/หาเวลาว่าง" เป็นปัญหา optimization ที่ LLM ทำได้ไม่ดี
    (LLM มักคำนวณเวลาผิด/วางทับกัน) — โปรเจกต์นี้จึงแบ่งงานให้ถูกเครื่องมือ:

      งานที่ใช้ Gemini (ภาษา/ตัดสินใจ)
        - แชท, แปลงข้อความเป็นกิจกรรม, วิเคราะห์ตาราง, สรุปสัปดาห์,
          แตกงานเป็น subtask
        - "เลือกว่าใครควรทำงานไหน" ในการกระจายงานกลุ่ม (ดูความเป็นธรรม+นิสัย)

      งานที่คำนวณเอง local (ต้องแม่นยำ)
        - หาช่วงเวลาว่าง (lib/freeTime.ts)
        - วางเวลาลงช่องว่างไม่ให้ชนกัน
        - Priority Score (lib/priorityScore.ts)

    => Gemini เลือก "ใคร" แล้วโค้ดคำนวณ "เมื่อไหร่" ให้ถูกต้อง 100%
       + มี fallback local ทุกจุดเมื่อ AI ใช้ไม่ได้

 8. จุดเด่น / นวัตกรรมของโปรเจกต์
========================================================================

  1. ระบบกลุ่มที่ AI หาเวลาว่างร่วมและกระจายงานอัตโนมัติ
     (ต่างจากปฏิทินทั่วไปที่แค่บันทึกกิจกรรม)

  2. สถาปัตยกรรม AI แบบ Hybrid (LLM + อัลกอริทึม)
     ที่เข้าใจข้อจำกัดของ LLM และเลือกใช้เครื่องมือให้ถูกงาน

  3. ความเป็นส่วนตัวในการแชร์ (แต่ละคนคุมได้ว่าจะเปิดเผยแค่ไหน)

  4. AI ปรับคำแนะนำตาม "นิสัย" และ "เวลาที่สะดวก" ของแต่ละคน

  5. ระบบทนต่อความผิดพลาด (AI ล่มก็ยังใช้งานได้ด้วย fallback)
